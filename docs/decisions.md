# 설계 결정과 이유

각 결정은 실제 문제를 진단한 결과다. **되돌리기 전에 왜 그랬는지 먼저 읽을 것.**

---

## 건드리면 안 되는 것

### `batch: false` — 요약 배치 금지

기사 여러 건을 한 프롬프트에 묶으면 토큰은 아끼지만 **모델이 일부 기사를 조용히 누락시킨다.** 초기 기사 유실의 원인으로 진단됐다. 기사 1건 = 호출 1회를 지킨다.

### VACUUM은 트랜잭션 밖에서

```python
conn.commit()
conn.isolation_level = None
conn.execute("VACUUM")
conn.isolation_level = ""
```

이 수정이 **5번 반복해서 날아갔다.** `db.py`를 새로 만들 때마다 빠뜨렸기 때문. 워크플로 초록불의 전제 조건이다.

### `sports_exclude`에 일반어 금지

"경기", "시즌", "리그", "우승", "전반기/후반기", "선수", "감독"을 넣으면 안 된다.

- **경기** → 경기도 지역 기사, 경기 전망 기사
- **시즌** → 시즌 프로모션
- **리그** → 리그오브레전드
- **우승** → 공모전 우승
- **전반기/후반기** → 반기 실적

실제로 "경기"를 넣었다가 경기도 기사가 전멸한 사고가 있었다. KBO·탈삼진·시청률처럼 **스포츠에만 쓰이는 말만** 넣는다.

### `KB` 단독 키워드 금지

`group_keywords`에 `KB`를 넣으면 **`KBO`가 매칭된다.** 야구 기사가 통과했던 원인. 또 `KB`가 브랜드 목록에 들어가면 관련성 키워드로 자동 편입되어 **모든 KB 기사가 무조건 통과**한다. 정식 명칭(`KB금융`, `KB국민은행`)만 쓴다.

## 수집

### 검색 기간 = 요청 시각 기준 24시간 고정

**대안이었던 것**: 직전 실행 시각 기준

**이유**: 매일 안 돌릴 수도 있어서 일관성이 없어진다. 월요일 예외 처리, 오버랩, 72시간 상한 같은 복잡도가 붙는다.

**감수사항**: 하루 이상 건너뛰면 그 사이 기사는 못 잡는다. 대신 자주 돌려도 "기열람" 중복 제거로 같은 기사가 반복 노출되지 않는다.

### 네이버·카카오 본사 제외

금융회사가 아니다. 게다가 인터넷·핀테크 그룹은 `standalone_mode: true`라 회사명이 그대로 검색어가 되는데, "네이버" 단독 검색은 웹툰·쇼핑·스포츠를 전부 긁어온다. 실제로 이것 때문에 실행이 13분으로 늘고 "절단: 네이버" 경고가 떴다.

`네이버페이`, `네이버파이낸셜`, `카카오뱅크`, `카카오페이` 등 **금융 계열만** 유지.

## 필터링

### 수집은 넓게, 판단은 본문 확보 후 로컬에서

검색 단계에서 미리 좁히면 놓치는 기사가 생긴다. 넓게 긁어온 뒤 로컬에서 판단한다. 네이버 API는 무료이므로 수집량은 비용이 아니다.

### 1차 스크리닝은 제목만으로

본문 추출은 건당 1~5초다. 1,800건을 다 긁으면 실행이 20분을 넘는다. 제목만으로 걸러 **~300건**만 추출한다.

### 제목에 단서 없으면 본문 리드로 판정

"KB국민은행, 새 시스템 가동" 같은 제목은 디지털 기사인지 알 수 없다. 이런 건 본문 **리드 400자**를 읽어 판정한다.

**리드만 보는 이유**: 한국 기사는 역피라미드라 주제가 리드에 온다. 뒤쪽 언급은 그 기사의 주제가 아니다.

**핵심 키워드만 인정하는 이유**: 관련성 목록 전체(122개)엔 앱 이름이 포함되어, CSR 기사에 "신청은 하나원큐 앱에서" 한 줄만 있어도 통과했다. 삼계탕 나눔 기사가 이렇게 뚫렸다. 주제어급 **49개**만 인정한다.

### 본문 읽을 가치가 없으면 미리 제외

`NON_DIGITAL_TOPICS` 63개(CSR·금리·실적·행사). 읽어봐야 어차피 제외될 기사에 1~5초를 쓸 이유가 없다. 이 규칙 없이는 실행이 **21분**까지 늘었다.

**순서가 중요하다** — 관련성 검사를 먼저 하므로 "AI 기반 금리 산정"은 '금리'가 있어도 통과한다.

### 종합기사는 태그 이름이 아니라 구조로 판정

`[주목! e금융]`, `[여의도단신]`, `[금융레이더]` — 태그 이름은 매체마다 계속 새로 생겨서 열거 방식은 한계가 있다. 또 회사명이 `하나`, `KB국민`처럼 잘려 매칭이 안 되기도 한다.

**대괄호 태그 + 구분자(·, /) 3개 이상** → 종합기사. 구조로 잡으면 새 태그도 자동으로 걸린다.

### 브랜드명은 관련성 키워드

`SOL LINK`, `하나원큐`, `KB Pay` 같은 앱·서비스 이름이 제목에 있으면 **그 자체로 디지털 기사**다. `BRAND_TO_COMPANY`의 키를 관련성 목록에 자동 편입한다. 매핑을 한 곳(classifier)에서만 관리하므로 새 앱은 한 번만 추가하면 된다.

### 보안 키워드는 디지털 맥락이 분명한 것만

`금융사기 예방`, `인증 강화`는 뺐다. 오프라인 노인 대상 예방교육 기사가 통과하던 원인. `보이스피싱`·`FDS`·`딥페이크`처럼 디지털 사안임이 분명한 것만 남긴다.

## 중복 제거

### 제목 토큰 방식이 주력

한국 기사는 **본문 simhash만으로 안 잡힌다.** 같은 사건을 다룬 기사끼리도 해밍거리가 14~28로 벌어진다. 제목 토큰 겹침이 훨씬 정확하다.

**실측**: Fast-Fit 송금 8건 → 3건, 탭앤페이 4건 → 1건, 카카오뱅크 몽골 6건 → 1건

### 한국어 조사 제거

`공무원연금공단`과 `공무원연금공단과`가 다른 토큰으로 갈려 중복을 놓쳤다.

**실측**: 신한은행 공무원연금공단 2건 겹침 0.20 → **0.40** (묶임), 다른 사건은 0.20 유지 (안 묶임)

어간이 2자 이상 남을 때만 조사를 뗀다.

## 요약

### 줄마다 역할 지정하지 않음

예전엔 "1줄 도입 / 2줄 변화 / 3줄 시사점"이었다. 본문 사실만 고르게 담는 방식으로 바꾼 이유:

1. 실제 용도가 **사실 파악**이지 임원 보고가 아님
2. 프롬프트가 짧아짐 (1,312자 → 430자)
3. **8b 모델도 충분히 해냄** — 70b와의 격차가 주로 "3번째 줄 추론"에서 났는데 그 요구가 사라짐

### 근거 검증 (`_grounded`)

모델이 요약할 내용을 못 찾으면 **프롬프트의 예시를 그대로 복창한다.** 골드만삭스 기사와 JP모건 기사에 똑같은 "KB AI Lab" 요약이 나온 실제 사고.

요약의 명사 토큰이 원문에 55% 이상 등장하는지 검증한다. 예시 복창은 겹침 **0.00**, 정상 요약은 **0.81**로 명확히 갈린다. 예시 복창뿐 아니라 모든 환각을 잡는다.

### 형식 실패는 1회만 재시도

형식 오류는 같은 프롬프트로 다시 불러도 대개 같은 결과다. 3회 재시도 + 8b 3회 = 최대 6회는 **한 건에 10,038토큰**(정상 6건치)을 태운다. 실패 8건이면 하루 쿼터의 절반이 증발한다.

### 본문 200자 미만은 호출 생략

토큰을 아끼면서 동시에 **환각의 근본 원인**을 없앤다. 짧은 본문을 받은 모델이 예시를 복창하는 것이 KB AI Lab 사고의 메커니즘이었다.

### 본문 정제 후 문장 단위 절단

실측 결과 본문의 **37%가 군더더기**(기자 프리픽스, 이메일, 사진 캡션, 저작권 문구)였다. 정제 후 자르면 같은 토큰에 실질 내용이 훨씬 많이 담긴다.

문장 중간에서 자르면 모델이 끊긴 문장을 해석하느라 품질도 떨어지고 토큰도 낭비된다.

## 저장

### 제외 기사는 DB에 저장하지 않음

HTML의 제외 목록 패널은 **현재 회차 것만** 보여준다. 즉 과거 회차 제외분은 저장만 되고 아무도 안 봤다. 메모리에서 HTML로 직접 전달하면 검수 기능은 그대로면서 DB만 가벼워진다.

**결과**: 6.4MB → 233KB (96% 감소)

중복 제거와 요약 캐시는 `delivered=1` 기사만 참조하므로 영향 없다.

### 본문 전문 미저장

`store_full_body: false`. DB 크기 절감. 대신 `retry_summary.py`는 URL로 본문을 다시 긁는다.

### HTML 생성 성공 후 delivered 마킹

생성이 실패하면 다음 실행에서 같은 기사를 다시 시도한다. 기사가 조용히 사라지지 않게 하는 장치.

## 실패 이력 (같은 실수 반복 방지)

| 사고 | 원인 | 교훈 |
|---|---|---|
| VACUUM 에러 5회 반복 | 파일 재생성 시 수정 누락 | 수정 전 기존 파일 확인 |
| "경기" → 경기도 기사 전멸 | 스포츠 키워드에 일반어 | 추가 전 회귀 테스트 |
| KBO 야구 기사 유입 | `KB` 단독 키워드 | 짧은 약어는 부분 매칭 위험 |
| KB AI Lab 예시 복창 | 프롬프트 few-shot 예시 | 근거 검증 필요 |
| 실행 21분 | 본문 확인 대상 폭증 | 읽을 가치 판단을 먼저 |
| 네이버 노이즈 폭증 | standalone_mode에 본사 추가 | 검색어 생성 방식 확인 |
| 삼계탕 기사 통과 | 본문 판정에 앱 이름 포함 | 핵심 키워드만 인정 |


### 영문 기사는 번역 요약 + 영문 전용 근거 검사
영문 본문(한글 비율 20% 미만)이면 프롬프트 앞에 번역 지시(`EN_NOTE`)를 붙이고 본문은 2,000자까지 싣는다.
근거 검사(`_grounded`)는 한글 단어를 영문 본문과 직접 비교할 수 없어서(2026-10: 영문 기사 4건이 근거
10~17%로 전부 '환각' 폐기) 영문 전용 `_grounded_en`으로 분기한다.
1) 프롬프트 예시 복창 차단 2) 요약에 남은 영문 고유명사의 절반 이상이 원문에 있을 것
3) 추적 중인 회사(별칭)가 원문에 영문으로 나오면 요약에도 그 회사가 있을 것.
한글 기사의 근거 검사와 프롬프트는 그대로다(옛/새 프롬프트 동일 확인). 한글보다 검증력이 약하다 —
영문 요약의 환각은 기준을 올리기보다 건수가 늘면 표본 점검으로 본다.
영문 '환각' 폐기분은 `backfill.retry_english`가 기사당 1회만 다시 요약한다.

### 해외(영문) 뉴스는 국내와 분리한 별도 트랙
국내 규칙(필터·중복·Groq 한도)을 해외에 그대로 쓰면 서로 망가진다. 그래서 워크플로·저장소·페이지·요약 엔진을 모두 나눴다.
- **concurrency 그룹을 분리** — 같은 그룹이면 대기 중인 국내 정기 실행이 해외 실행에 밀려 취소될 수 있다.
- **커밋 파일이 겹치지 않는다** — 해외 실행이 국내 HTML을 다시 만들면 rebase 충돌이 난다(2026-10-07 충돌 표시 배포 사고와 같은 유형).
  그래서 해외는 `output/foreign.html`을 따로 만들고 국내 페이지에는 링크만 건다.
- **요약은 구독 Claude만** — 해외는 건수가 적고(하루 20건) 영문 번역 요약이라 Groq 무료 한도를 쓰지 않는다.
  토큰이 없으면 수집을 생략한다(본문만 긁고 요약을 못 하면 헛수고이고, 다음 실행에서 다시 해야 한다).
- **중복 3단계**: 제목 토큰 겹침 → 본문 핵심어 40개 겹침(≥0.5) → 요약 핵심어 겹침(≥0.35, 같은 회사 기사끼리만).
  같은 DTCC 발표를 4개 매체가 쓴 것을 실측으로 확인해 넣었다. 묶인 다른 매체 기사는 "비슷한 기사" 팝업으로 남긴다.
- **대상 회사가 주제인가**: 회사 별칭이 제목이나 본문 앞 600자에 있어야 한다(Mastercard 기사가 HSBC 검색에 걸린 사례).
  영문 별칭은 단어 경계로 비교한다(`HSBC`가 다른 단어 안에 들어 있는 경우 방지).
- 구글 뉴스 링크는 해독이 필요한데 짧은 시간에 많이 풀면 차단된다(로컬 실측: 약 90회 뒤 429). 그래서 Bing을 주 수집원으로 하고
  구글은 15회·연속 3회 실패 시 중단하는 보조로만 쓴다. GitHub Actions IP에서는 구글이 더 빨리 막힐 수 있다.
- 원칙 4(제외 기사도 보존)는 해외에도 적용한다: 걸러진 후보는 사유와 함께 페이지에 남는다(하루 400건까지).
- **제목도 한국어로 번역**하되 기사 1건당 짧은 호출 1번이다(제목을 묶어 번역하면 일부가 조용히 빠질 수 있다 — 요약 배치 금지와 같은 이유).
  반영이 확정된 기사만 번역하고, 결과는 `valid_title_ko`로 검증한다: 한글이 있을 것, 번역문의 영문 단어는 원제목에 있던 것일 것
  (없던 고유명사 = 환각), 거절·되묻기 문장 불가. 실패하면 영문 제목을 그대로 보이고 다음 실행에서 1번만 재시도한다.
- **첫 실제 실행(2026-10-29)에서 나온 보정**: ① RSS의 기간 옵션(Bing `freshness`, Google `when:`)이 지켜지지 않아 1년 전·2개월 전 기사가
  들어왔다 → `max_age_days: 3`을 게재일로 직접 검사(게재일 불명도 제외). ② 은행이 투자자·주선자로만 나오는 기사(스타트업 투자 유치,

### 요약 전 중복 판정 (2026-10-29)
**문제**: 요약 후에야 중복으로 버려지는 기사가 14일간 434건(하루 약 31건)이었다. 오늘 한 실행의 첫 40건 묶음에서는 26건을 요약한 뒤 12건(46%)을
버렸다. 요약은 Groq 분당 토큰 한도(분당 4~5건)가 병목이라 이 헛수고가 실행 시간(오늘 12~24분)과 하루 토큰 예산을 크게 잡아먹는다.
**방법**: `ddp.dedup_before_summary` — 요약(LLM) 없이 본문만으로 판정한다.
1) 과거와 같은 사건: 최근 3일 반영된 같은 회사 기사의 요약 핵심어가 새 기사 본문(앞 1,500자)에 들어 있는 비율 ≥ 0.65, 공통 6개 이상.
2) 묶음 안 중복: 같은 날·같은 회사 기사끼리 본문 핵심어 겹침(짧은 쪽 기준) ≥ 0.50 → 점수 높은 대표 1건만 요약.
**기준선 근거(실측)**: 요약 후 중복으로 버려졌던 기사와 정상 반영 기사 각 120건 안팎의 본문을 다시 받아 임계값별 포착률·오탐을 쟀다.
과거 0.65에서 포착 57%, 묶음 0.50에서 포착 54%. 정상 쪽에서 '오탐'으로 잡힌 쌍을 눈으로 확인하니 대부분 실제 같은 사건(현대해상 AX 페스티벌,
삼성화재 AI 어드바이저, 부산은행 59주년 등)이라, 0.65/0.50은 보수적인 선택이다. 낮추면(0.45/0.35) 포착률이 82~89%로 오르지만 오탐도 11~12%로 는다.
**안전장치**: ① 기존 요약 기반 판정(`dedup_by_summary`)은 그대로 둔다 — 놓친 것은 그쪽이 잡는다. ② 걸러진 기사는 기존 중복과 같은 사유 형식
(`기열람(동일 사건 0.70: 제목)`, `중복(본문유사 0.62 | 대표: 제목)`)으로 제외 로그·검수 목록·'비슷한 기사' 팝업에 남는다(원칙 4).
③ 제목에 회사명이 없으면 회사 일치 조건을 못 채워 판정하지 않는다(기존 요약 후 판정과 같은 조건). ④ `dedup.presummary: false`로 끌 수 있다.
**검증**: 단위 테스트(과거·묶음·회사 게이트·짧은 본문·설정 끄기), `main.main()` 전체 흐름 시험(요약 호출 3회→2회).

### 네이버 수집: 기간 밖 기사가 나온 페이지에서 바로 중단 (2026-10-30)
**문제**: 키워드 668개를 호출 1회로 끝낼 수 있는데 평균 3.28회 불렀다(실행당 약 2,200회, 초당 9회 제한이라 약 4분). 결과가 최신순(`sort=date`)인데도
'페이지 전체가 기간 밖'일 때만 멈추고 한 페이지를 더 확인했기 때문이다. 하루 호출량은 최대 14,700회로 일일 한도(25,000회)에 가까워지고 있었다.
**방법**: 한 페이지에서 기간보다 오래된 기사가 `stop_after_old_items`(기본 1)개 이상 나오면 그 페이지의 기간 내 기사를 담은 뒤 중단한다. 최신순이라 뒤 페이지는 전부 더 오래됐다.
**검증**: ① 합성 피드 300개(페이지 수·구간 무작위)에서 기간 내 기사 결과가 전부 동일, 호출은 항상 같거나 적음. ② 실제 API A/B(같은 키워드, 예전 방식 대 새 방식):
구간 1시간 133→60회(−55%), 3시간 137→60회(−56%), 22시간 113→41회(−64%), 구간 안 기사 874건 중 놓친 것 0건.
③ 부수 효과: 500건 상한 페이지에 오래된 기사가 섞여 있어도 '절단'으로 경고하던 거짓 경고가 사라진다(상한 뒤에 구간 안 기사가 없으므로 실제 절단이 아니다).
**끄기**: `naver_api.stop_after_old_items: 0`이면 예전 방식. `extra_page_after_old`는 이 규칙이 꺼졌을 때만 의미가 있다.
